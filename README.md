# LoopDish

LoopDish is a dinner log and weekly meal planner. This first slice uses TanStack Start, React, Convex, WorkOS AuthKit, StyleX, Vite+, and a small hand-written service worker.

## Run it

Requirements: Node.js 22 or newer, [Vite+](https://viteplus.dev/), and a Convex account. Vite+ reads the pinned pnpm version from `package.json`.

```sh
vp install
pnpm dev
```

The first run opens the Convex login and project setup flow. Convex writes `VITE_CONVEX_URL` to `.env.local`, deploys the functions in `convex/`, and starts the web app at `http://localhost:3000`.

For frontend-only work, copy `example.env` to `.env.local`, replace the URL with a real Convex deployment URL, and run:

```sh
pnpm dev:web
```

Add these WorkOS settings to `.env.local` for local authentication:

```sh
WORKOS_CLIENT_ID=client_...
WORKOS_API_KEY=sk_test_...
WORKOS_COOKIE_PASSWORD=<at-least-32-random-characters>
WORKOS_REDIRECT_URI=http://localhost:3000/api/auth/callback
```

Register `http://localhost:3000/api/auth/callback` as a redirect URI and `http://localhost:3000` as a CORS origin in WorkOS. Configure Google as the only enabled authentication method in the WorkOS dashboard.

Run `vp check`, `vp test`, and `vp build` for validation. Vite+ uses Oxfmt, Oxlint, and tsgo for these checks.

## Amp orb previews

Store `WORKOS_API_KEY` and `WORKOS_COOKIE_PASSWORD` as Amp project secrets. Store `WORKOS_CLIENT_ID` as a project environment variable. The declared preview service reads Amp's current `PUBLIC_URL` when it starts and registers that exact origin and `/api/auth/callback` redirect URI with WorkOS. Portal URLs can therefore change between orbs without manual WorkOS edits.

## Dependency security

pnpm refuses package versions published less than five days ago, including pinned and transitive versions. It also blocks exotic transitive sources and fails installation when a dependency introduces an unreviewed install script. These rules live in `pnpm-workspace.yaml`; keep any future exceptions narrow and version-specific.

## Current scope

- Add dishes to the shared household collection
- Name a household and invite other signed-in people with a private, one-use link
- Plan one dinner per day
- Mark a planned dinner as eaten
- See recent dinner history and live updates from Convex
- Get new-dish ideas and a draft for next week from Cloudflare Workers AI
- Install the production build as a PWA
- Sign in with Google through WorkOS AuthKit

Each signed-in WorkOS user starts with a private household. People who accept an invite share its dishes, weekly plan, and dinner history.

## AI suggestions

Create a Cloudflare Workers AI API token with `Workers AI - Read` and `Workers AI - Edit`
permissions. Configure the Convex project first if this checkout does not have a `.env.local` file:

```sh
pnpm exec convex dev --once
```

Then add the account ID and token to the Convex deployment rather than the web app:

```sh
pnpm exec convex env set CLOUDFLARE_ACCOUNT_ID <account-id>
pnpm exec convex env set CLOUDFLARE_AUTH_TOKEN <api-token>
```

LoopDish sends saved dish names, notes, and household meal history to Cloudflare when a signed-in
member requests suggestions. The result remains a preview until the member adds a dish or confirms
the weekly plan. Each household can make five AI requests in a rolling 24-hour period.

## PWA note

The service worker is explicit rather than generated by `vite-plugin-pwa`. As of this setup, that plugin has an unresolved production-build incompatibility with TanStack Start's Vite environment build. The current worker uses network-first navigation and caches only the app shell fallback and static PWA assets. Convex data still requires a connection; durable offline mutations are not implemented yet.
